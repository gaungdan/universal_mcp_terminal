# Universal MCP Terminal MCP 接入指南

> 本文面向需要在 AI 客户端中接入 Universal MCP Terminal 的使用者与集成开发者。
> 协议实现：`crates/mcp-server/**`；Token 与授权：`crates/access-control/**`。

## 一、服务地址与认证

| 项目 | 默认值 | 说明 |
|---|---|---|
| 监听地址 | `127.0.0.1` | 默认只监听回环地址 |
| 端口 | `47321` | 可在「系统设置」中修改 |
| Endpoint | `/mcp` | `Router::nest_service("/mcp", ...)` |
| 完整地址 | `http://127.0.0.1:47321/mcp` | 首页「快速开始」展示当前实际地址 |
| Transport | Streamable HTTP | 基于 `rmcp` 的 `StreamableHttpService` |
| Authentication | Bearer Token | 每个请求都必须携带 |

请求头格式：

```http
Authorization: Bearer umt_xxxxxxxx_<64 位十六进制随机体>
```

Token 只能在「访问控制」或首页快速开始中创建；**明文只在创建成功时显示一次**。

> 认证阶段（缺少、格式错误、未知、禁用或已撤销的 Token）返回 HTTP 401。
> 已认证但未授权连接等错误通过 MCP JSON-RPC 返回 `code = -32001`，
> `data.code = "access_denied"`。

## Token 权限（补充）

Token 只有两种权限等级：

| 权限 | 允许 | 禁止 |
|---|---|---|
| `ReadOnly`（默认） | 查询类命令、只读管道、查看日志/进程/网络/文件 | 文件写入、配置修改、服务变更、重定向、命令替换、解释器、未知命令 |
| `WriteAccess` | ReadOnly 全部能力 + 普通文件/配置/服务操作 | `sudo`、`su`、`doas`、`pkexec` 等提权命令；灾难性删除/格式化/关机命令 |

- `ReadOnly` 采用允许清单，无法可靠判断的复杂命令会被拒绝，而不是默认放行。
- `sudo` 等提权命令对所有 Token 一律拒绝；但命令过滤无法保证绝对安全，最终边界是连接账号的系统权限。
- 交互式终端默认关闭：`ReadOnly` 永远不可用；`WriteAccess` 还需在 Token 上开启 `allow_interactive`。
- 开启交互式终端后等同于完整 Shell，无法逐条过滤输入；请只授权给可信客户端。

## 二、标准配置示例

```json
{
  "mcpServers": {
    "universal-mcp-terminal": {
      "transport": "streamable-http",
      "url": "http://127.0.0.1:47321/mcp",
      "headers": {
        "Authorization": "Bearer YOUR_ACCESS_TOKEN"
      }
    }
  }
}
```

- `YOUR_ACCESS_TOKEN` 必须替换为在访问控制页面创建的 Token。
- 仓库与默认配置中**不得**出现真实 Token。
- 部分客户端使用 `"type": "http"` 而不是 `"transport": "streamable-http"`，字段名以对应客户端官方文档为准。

## 三、工具清单

所有工具都要求 Bearer Token；涉及连接的工具还会校验 Token 是否被授权访问该连接。
返回值为 `CallToolResult` 的结构化 JSON（`structuredContent`）。

### 1. `list_connections`

参数：无。

返回：

```json
{
  "connections": [
    {
      "connection_id": "uuid",
      "name": "Production Linux",
      "protocol": "ssh",
      "description": "生产环境",
      "capabilities": ["exec", "interactive_terminal", "shell", "terminal_resize"],
      "enabled": true
    }
  ],
  "total": 1
}
```

只返回「已授权且启用」的连接；未授权连接连名称都不会暴露；不含任何凭据。

### 2. `get_connection_info`

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `connection_id` | string(UUID) | 是 | 连接 ID |

返回在 `list_connections` 单项的基础上增加：

```json
{
  "secret_fields": ["password", "private_key"],
  "has_stored_secrets": true
}
```

`secret_fields` 只列出 Provider Schema 中声明为 `secret` 的字段名，不返回值。

### 3. `test_connection`

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `connection_id` | string(UUID) | 是 | 连接 ID |

执行真实握手/认证（不是只探测端口），返回：

```json
{
  "ok": true,
  "message": "SSH 认证成功（Host Key SHA256:...）",
  "latency_ms": 123,
  "steps": [
    { "name": "TCP 连接", "status": "passed", "message": null, "duration_ms": 12 },
    { "name": "SSH 握手", "status": "passed", "message": "SHA256:...", "duration_ms": 80 },
    { "name": "SSH 认证", "status": "passed", "message": null, "duration_ms": 31 }
  ],
  "suggestion": null,
  "connection_id": "uuid"
}
```

`steps[].status`：`passed` / `failed` / `skipped`。失败时 `ok = false`，`suggestion` 给出排查方向。

### 4. `open_session`

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `connection_id` | string(UUID) | 是 | 连接 ID |
| `rows` | integer | 是 | 终端行数，必须 > 0 |
| `cols` | integer | 是 | 终端列数，必须 > 0 |
| `terminal_type` | string | 否 | 例如 `xterm-256color` |

返回：

```json
{
  "session_id": "uuid",
  "connection_id": "uuid",
  "protocol": "ssh",
  "state": "connected",
  "rows": 24,
  "cols": 80,
  "started_at": 1760000000000
}
```

### 5. `execute_command`

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `connection_id` | string(UUID) | 二选一 | 自动创建临时会话并在结束后关闭 |
| `session_id` | string(UUID) | 二选一 | 在已有会话中执行 |
| `command` | string | 是 | 非空命令 |
| `working_directory` | string | 否 | 工作目录 |
| `timeout_ms` | integer | 否 | 默认 30000，范围 1–600000 |

`connection_id` 与 `session_id` 同时提供或都不提供都会返回 `validation`。

返回：

```json
{
  "session_id": "uuid",
  "connection_id": "uuid",
  "state": "succeeded",
  "exit_code": 0,
  "stdout": "...",
  "stderr": "",
  "duration_ms": 42,
  "truncated": false
}
```

`state`：`sent` / `running` / `succeeded` / `failed` / `timed_out` / `unknown`。
网络中断会记录为 `unknown`（命令可能已在远端执行），不要当成简单的失败。

### 6. `send_input`

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `session_id` | string(UUID) | 是 | 会话 ID |
| `input` | string | 是 | 原始输入，可包含换行 |

返回：

```json
{ "session_id": "uuid", "bytes_sent": 6 }
```

### 7. `read_output`

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `session_id` | string(UUID) | 是 | 会话 ID |
| `cursor` | integer(u64) | 是 | 上次返回的 cursor，首次传 0 |
| `max_bytes` | integer | 否 | 默认 65536，范围 1–1048576 |

返回：

```json
{
  "session_id": "uuid",
  "cursor": 128,
  "text": "...",
  "eof": false,
  "truncated": false
}
```

`truncated = true` 表示因缓冲上限丢失了中间输出，调用方应意识到输出不完整。

### 8. `resize_terminal`

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `session_id` | string(UUID) | 是 | 会话 ID |
| `rows` | integer | 是 | 必须 > 0 |
| `cols` | integer | 是 | 必须 > 0 |

协议未声明 `terminal_resize` 时返回 `unsupported_capability`。返回：

```json
{ "session_id": "uuid", "rows": 40, "cols": 120, "resized": true }
```

### 9. `close_session`

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `session_id` | string(UUID) | 是 | 会话 ID |

返回：

```json
{ "session_id": "uuid", "closed": true }
```

关闭后再次操作该会话会返回 `not_found` 或 `conflict`（会话已关闭）。

### 10. `read_file`

只读读取远程文件分块，当前由 SSH Provider 通过 SFTP 实现；协议必须声明 `file_read` 能力。

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `connection_id` | string(UUID) | 是 | 连接 ID |
| `path` | string | 是 | 远程文件绝对路径 |
| `offset` | integer(u64) | 否 | 起始字节偏移，默认 0 |
| `max_bytes` | integer | 否 | 单次读取字节数，默认 65536，上限 131072 |

返回：

```json
{
  "connection_id": "uuid",
  "path": "/etc/os-release",
  "offset": 0,
  "next_offset": 400,
  "size": 400,
  "eof": true,
  "data_base64": "UFJFVFRZX05BTUU9..."
}
```

客户端循环调用直到 `eof=true`，本地拼接后自行校验哈希。ReadOnly 与 WriteAccess 都允许调用；Telnet 不支持该能力。

## 四、错误码

MCP 错误响应形如：

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "error": {
    "code": -32001,
    "message": "访问被拒绝：Token 未被授权访问连接 Production Linux",
    "data": { "code": "access_denied" }
  }
}
```

| `data.code` | 含义 | MCP 错误码 | 常见原因 |
|---|---|---|---|
| `access_denied` | 认证或授权失败 | `-32001` | 缺少/错误 Bearer、Token 禁用/撤销/过期、连接禁用、未授权、Host Key 未知或不匹配 |
| `unsupported_capability` | 协议不支持该能力 | `-32003` | 对 Telnet 调用 `resize_terminal`、对无 `exec` 能力的协议调用 `execute_command` |
| `not_found` | 资源不存在 | `RESOURCE_NOT_FOUND` | 连接/会话/工具/审计记录不存在；跨 Token 操作会话按不存在处理 |
| `validation` | 参数或配置校验失败 | `INVALID_PARAMS` | ID 格式错误、`rows/cols = 0`、缺少必填参数、配置字段非法 |
| `timeout` | 操作超时 | `-32000` | 连接、认证或命令执行超过超时时间 |
| `conflict` | 状态冲突 | `-32000` | 活动会话数达上限、会话已关闭、已撤销 Token 不能恢复 |
| `storage` | 持久化/密钥错误 | `INTERNAL_ERROR` | 数据库异常、密文损坏、密钥版本不匹配 |
| `external` | 外部依赖错误 | `-32000` | 网络断开、协议 I/O 异常 |
| `internal` | 内部错误 | `INTERNAL_ERROR` | 未归类的实现错误 |

统一约定：错误信息中不会出现密码、私钥、完整 Token 或密文。

## 五、常见客户端配置位置

不同客户端的配置文件位置与字段名差异较大，下表只给出常见入口，**以各客户端官方文档为准**：

| 客户端 | 常见配置位置/方式 | 备注 |
|---|---|---|
| Claude Code | 项目根 `.mcp.json`，或 `claude mcp add` 命令 | 支持项目级/用户级作用域，具体字段以官方文档为准 |
| Codex | `~/.codex/config.toml` 的 MCP 配置段 | 是否支持 Streamable HTTP 与具体键名以官方文档为准 |
| Cursor | `~/.cursor/mcp.json` 或项目内 `.cursor/mcp.json` | 以官方文档为准 |
| OpenCode | 项目 `opencode.json` 的 MCP 配置段 | 键名与 transport 支持以官方文档为准 |

无论使用哪个客户端，目标都是配置同一个 URL 与 `Authorization: Bearer <token>` 请求头。

## 六、故障排查

### 6.1 认证失败（客户端显示未授权 / `-32001`）

1. 确认请求头是 `Authorization: Bearer <token>`，不是 `Basic`，也没有多余空格。
2. 确认 Token 未过期、未被禁用或撤销（访问控制页面查看状态与最后使用时间）。
3. 确认 Token 已被授权访问目标连接（Token 详情页的授权开关）。
4. 不要在工具参数里传 Token；服务端只接受 HTTP header。

### 6.2 端口占用

启动失败时错误信息为「MCP 服务无法监听 127.0.0.1:47321：...（端口可能已被占用）」，
`McpStatus.last_error` 会保留原因。排查：

```powershell
Get-NetTCPConnection -LocalPort 47321 -ErrorAction SilentlyContinue
```

在系统设置中改用其他端口，或停止占用该端口的进程后重试。

### 6.3 未授权连接

调用 `list_connections` 看不到某个连接，或 `get_connection_info` 返回 `access_denied`：

1. 连接是否被禁用（连接管理页面）。
2. Token 是否被授权访问该连接（访问控制 → Token 详情）。
3. 是否把 `connection_id` 换成了另一个 Token 有权限、但当前 Token 无权限的连接（后端会拒绝，无法通过参数绕过）。

### 6.4 Host Key 未知

SSH 连接返回 `access_denied`，消息包含 `未知 Host Key：SHA256:...`：

1. 先调用 `test_connection`，在 `steps` 中查看服务端实际指纹。
2. 与目标服务器的已知指纹核对，确认不是中间人攻击。
3. 只有人工确认后，才可通过桌面端信任流程把指纹写入 `ssh_host_keys`。
4. MCP 路径**不提供**信任未知 Host Key 的工具；未保存指纹时无人值守调用一律拒绝。
5. 指纹与已保存值不一致（`HostKeyMismatch`）时必须排查服务端是否更换密钥或被劫持，不能直接覆盖。

### 6.5 其它常见问题

- `validation`：检查 UUID 格式、`rows/cols` 是否大于 0、`connection_id` 与 `session_id` 是否只传一个。
- `timeout`：确认网络与目标服务状态；`timeout_ms` 上限为 600000。
- 会话被自动关闭：默认空闲 30 分钟回收，或活动会话数达到 32 个上限。
